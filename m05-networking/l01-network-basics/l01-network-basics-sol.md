# Lab 5.1 – Lösung: Netzwerkverwaltung in Containern

IDs, IP-Adressen und Uhrzeiten unterscheiden sich je Rechner und Start.

## Aufgabe 1: Netzwerke anzeigen

```bash
docker network ls
```

```text
NETWORK ID     NAME            DRIVER    SCOPE
7cb3d17a9f49   bridge          bridge    local
a23dd1e574d8   host            host      local
9c257c845e77   none            null      local
19fdbaa7a449   hello_default   bridge    local
```

`bridge`, `host` und `none` legt Docker selbst an. `hello_default` stammt von Compose: Projektname `hello` (Ordnername) plus `_default`. Weitere Einträge (z. B. aus anderen Übungen oder `docker_gwbridge` nach einem Swarm-Test) stören nicht.

## Aufgabe 2: Projektnetzwerk lesen

```bash
docker network inspect hello_default
```

```text
[
    {
        "Name": "hello_default",
        "Scope": "local",
        "Driver": "bridge",
        "IPAM": {
            "Driver": "default",
            "Config": [
                {
                    "Subnet": "172.18.0.0/16",
                    "Gateway": "172.18.0.1"
                }
            ]
        },
        "Internal": false,
        "Labels": {
            "com.docker.compose.network": "default",
            "com.docker.compose.project": "hello",
            …
        },
        "Containers": {
            "43a7af3e8d8c…": {
                "Name": "hello-frontend-1",
                "IPv4Address": "172.18.0.3/16",
                …
            },
            "c0f0edd9ccaa…": {
                "Name": "hello-backend-1",
                "IPv4Address": "172.18.0.2/16",
                …
            }
        },
        …
    }

```

| Feld | Wert | Bedeutung |
| --- | --- | --- |
| `Driver` | `bridge` | Compose nutzt den Standardtreiber |
| `Subnet` | `172.18.0.0/16` | alle Container bekommen eine Adresse `172.18.x.x` |
| `Gateway` | `172.18.0.1` | Ausgang zum Host und ins Internet |
| `Containers` | Frontend `.3`, Backend `.2` | beide Dienste hängen im selben Netzwerk |

Kürzer, nur Namen und IPs:

```bash
docker network inspect hello_default --format '{{range .Containers}}{{.Name}} {{.IPv4Address}}{{"\n"}}{{end}}'
```

```text
hello-frontend-1 172.18.0.3/16
hello-backend-1 172.18.0.2/16
```

Die Hello-Seite zeigt dieselben Adressen: `Frontend: 43a7af3e8d8c (172.18.0.3)` und `Backend: c0f0edd9ccaa (172.18.0.2) um 21:38:49`. Der Hostname im Container ist die kurze Container-ID.

## Aufgabe 3: Backend per Namen erreichen

```bash
docker compose exec frontend curl -s http://backend
```

```text
{"hostname":"c0f0edd9ccaa","ip":["172.18.0.2"],"now":"21:38:49"}
```

```bash
docker compose exec frontend getent hosts backend
docker compose exec frontend cat /etc/resolv.conf
```

```text
172.18.0.2        backend  backend

# Generated by Docker Engine.
…
nameserver 127.0.0.11
options ndots:0
…
```

`docker compose exec <dienst>` braucht den Dienstnamen aus `compose.yml`, nicht den Containernamen. Ohne Port in der Adresse nutzt `curl` Port 80, deshalb ist `http://backend` dasselbe wie `http://backend:80`. Der Name löst über den eingebauten DNS-Server `127.0.0.11` auf die IP aus `inspect` auf.

## Aufgabe 4: Einzelcontainer in der Standard-Bridge und im Projektnetzwerk

```bash
docker run --rm busybox:1.37 wget -qO- -T 3 http://backend
```

```text
wget: bad address 'backend'
```

```bash
docker run --rm --network hello_default busybox:1.37 wget -qO- -T 3 http://backend
```

```text
{"hostname":"c0f0edd9ccaa","ip":["172.18.0.2"],"now":"21:40:12"}
```

Ohne `--network` landet der Container in der Standard-Bridge: dort gibt es weder den Namen `backend` noch eine Verbindung ins Netzwerk `hello_default`. Mit `--network hello_default` hängt er im Projektnetzwerk und wird wie ein weiterer Dienst behandelt. `--rm` entfernt den Container danach automatisch.

## Aufgabe 5: Vom eigenen Rechner aus

```bash
curl http://backend
```

```text
curl: (6) Could not resolve host: backend
```

```bash
curl http://localhost:8080
```

```text
<!doctype html>
<html lang="de">
<head><meta charset="utf-8"><title>Hello-App 2.0.0</title></head>
<body style="background:yellow; font-family:sans-serif; padding:2rem;">
  <h1>Hello World 2.0.0</h1>
  <p><b>Frontend:</b> 43a7af3e8d8c (172.18.0.3)</p>
  <p><b>Backend:</b> c0f0edd9ccaa (172.18.0.2) um 21:41:03</p>
  …
```

Der eigene Rechner ist nicht Teil des Docker-Netzwerks. Er erreicht nur den veröffentlichten Port 8080 des Frontends; das Backend hat keinen veröffentlichten Port und ist von außen gar nicht erreichbar.

**Warum `backend:80` in Compose funktioniert:** Compose legt das Netzwerk `hello_default` an, hängt beide Dienste hinein und meldet jeden Dienstnamen beim DNS-Server `127.0.0.11` an. Das Frontend fragt nach `backend` und bekommt die aktuelle IP des Backend-Containers.
